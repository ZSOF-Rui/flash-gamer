## 1. 项目定位与功能边界

### 1.1 它做什么

1. **解析**：用户粘贴 4399 / 7k7k 游戏页 URL，主进程用隐藏窗口加载页面、观察网络请求、读取页面变量和 `embed/object` 声明，得到一组 SWF 候选；下载、校验、去重后入库。
2. **保存**：游戏本体写到 `items/<id>/main.swf`，封面写到 `items/<id>/cover.*`，条目写入 `library.json`；同一个 SHA-256 只保存一份。
3. **播放**：本地 HTTP 服务提供 `/play/:id`，页面里用 Ruffle 播放 SWF；4399 附加资源通过 `/m/...` 镜像代理并缓存，保证断网可玩。主窗口与独立游戏窗口共用同一套播放页，点「停止运行」可卸载主窗口播放器并关闭所有独立游戏窗口。
4. **网页浏览**：内置 `<webview>` 浏览器，可访问 4399 / 7k7k、登录账号，并把当前页交给解析器；v0.3.2 起在 4399 游戏页注入 Ruffle，网页里的 Flash 直接运行，同时收起健康忠告/加载遮挡层。
5. **更新**：启动后或手动检查静态 JSON 清单，取多源中的最高版本，流式下载并校验 size + SHA-256，再启动 NSIS 安装程序。

### 1.2 它刻意不做

- 不安装 Adobe Flash Player，不使用系统浏览器插件。
- 不打开游戏网页来播放；播放器只加载 SWF 本体和必要的附加资源。
- 不捆绑安装器、不改浏览器主页、没有遥测上报。
- 不把游戏上传到任何服务器；解析、下载、播放、缓存都在本机完成。
- 网页内注入只“运行页面里已有的 SWF”，**不做内嵌游戏抽取**；205551 这类壳游戏必须在网页里解析入库，由播放器抽取内层 `play.swf` 才能玩。

```bash

npm install          # postinstall 会执行 scripts/vendor-ruffle.js

```

如果 `vendor/ruffle` 缺失或升级 Ruffle：

```bash

```

## 6. 架构与关键流程

### 6.1 组件图

```text

│       onBeforeSendHeaders（Referer / Cookie）                                     │
│       onHeadersReceived（CORS，仅播放器/浏览器 guest）                             │
```

### 6.2 启动序列

1. `app.commandLine.appendSwitch` 关闭后台节流/渲染后台化（保证独立窗口游戏不卡）。
2. `resolveDataDir()` → 建目录 → 旧数据迁移。
3. `app.whenReady()`：
   - 创建 `Library(DATA_DIR)`；
   - 创建独立更新 session `session.fromPartition('flash-gamer-updater')`，交给 `Updater`；
   - `createServer(...)` 启动本地 HTTP 服务（优先 43199，冲突则 +1 到 +39，最后随机）；
   - `registerIpc()`；
   - `session.defaultSession.setProxy({ proxyRules: 'http=127.0.0.1:<port>', proxyBypassRules: '127.0.0.1,localhost' })`；
   - 注册 `onBeforeRequest`、`onBeforeSendHeaders`、`onHeadersReceived`；
   - `createWindow()` 打开主窗口；
   - `did-finish-load` 后：如果设置 `AP_SMOKE` 就跑 smoke；否则 6 秒后自动检查更新（`AP_UPDATE_DISABLE=1` 可关）。
4. 主窗口加载 `http://localhost:<port>/?t=<token>`，服务端种下 `ap_session` Cookie。

### 6.3 解析流程（粘贴链接 / 网页“解析此页”）

1. 渲染层调用 `window.api.inspect(url)` 或 `browserApi.parse(url)` → IPC `inspect` / `browser:parse`。
2. 主进程 `inspectPage({ pageUrl, tmpDir, onProgress })`：
   - 创建隐藏的 `BrowserWindow`（独立 session，禁用图片等以提速）；
   - 加载页面，注入脚本读取 `_strGamePath`、`_winPath`、`_htmlPath`、`embed/object`、页面内 `.swf` 引用；
   - 监听网络请求，收集 SWF 响应（含 Referer/Cookie/Content-Length）；
   - 关闭隐藏窗口。
3. 候选构建与过滤：
   - 跳过广告 `cell.swf`（4399 的 3 KB 占位壳）；
   - 跳过广告域名；
   - 声明候选、embed/object、页面引用、网络抓包合并去重；
   - 对候选下载并判断：真 SWF（FWS/CWS/ZWS）→ 保存；HTML 包装页 → 从 HTML 里提取 `.swf` 引用，用包装页 URL 作 Referer 递归下载；
   - 按 `via` 优先级 + 同站加分 + 跨站 4399/7k7k 罚分排序；同分取更大文件；按 SHA-256 去重。
4. 用户在候选列表选择（或自动选第一个），主进程 `buildItemFromCandidate`：
   - 读取 SWF 尺寸/flashvars；
   - 抓封面；
   - 计算 SHA-256，查重；
   - 写入 `items/<id>/main.swf`、封面、`library.json`。
5. 渲染层刷新库列表并自动播放。

候选优先级（`inspector.js`）：

```text
declared / wrapper : 4
embed / object     : 3
capture            : 2
其他（html 引用等）: 1
```

同站 +2，同主域 +1，4399 页面里的 7k7k 文件或反之 -2（直接判负）。

### 6.4 播放流程

1. 渲染层在主窗口 iframe 或独立窗口加载 `http://localhost:<port>/play/<id>`。
2. 服务端：
   - `ensureInnerSwf(item)`：如果 `items/<id>/play.swf` 不存在，读取 `main.swf`，尝试抽取内嵌游戏；成功则写 `play.swf`；
   - 设置 `activeGame = item`（供代理补 Referer/Cookie）；
   - 用 `buildBoot(item)` 生成启动 JSON，注入 `player.html` 的 `__BOOT__`；
   - 为内联 `<script>` 加 nonce，CSP 允许 `unsafe-eval` / `wasm-unsafe-eval` / `blob:`。
3. `player.html`：
   - 配置 Ruffle（`publicPath` 本地 vendor、`autoplay`、`letterbox`、`allowNetworking` 等）；
   - 把 `<ruffle-player>` 伪装成 `EMBED`：设置 `id/name/type/allowScriptAccess/allowNetworking/allowFullScreen`，并覆盖 `nodeName`/`tagName`；
   - 拦截 4399 壳的 `setTimeout("fl_obj.cloneNode()...")` 克隆替换；
   - 监听错误，写到 `__apErrors` 供 smoke 读取。
4. SWF 地址：
   - 有 `originalUrl`：`/m/<id>/<base64url(dir)>/<fileName>`，由本地服务代理到原站并缓存；
   - 无 `originalUrl`（本地导入）：`/file/<id>/<fileName>`；
   - 如果 `play.swf` 存在且请求的是主 SWF（`originalUrl` 同 origin+pathname，或 `/file/<id>/main.swf`），直接返回 `play.swf` 并加 `X-Ap-Inner: 1`。
5. 独立窗口：`openGameWindow(id)` 创建 1000×760、黑色背景、`backgroundThrottling:false` 的窗口，加载同一个 `/play/:id`，按 id 去重；共享默认 session，所以 `ap_session` 直接可用。
6. 停止运行：渲染层 `stopAll()` 先把 `state.playing=false`、清空 `state.windows`、把 iframe 置为 `about:blank`、播放区显示“已停止运行，点击「开始游戏」重新启动”，再调 `window.api.stopGames()` → IPC `library:stop` → `closeGameWindows()` 关闭所有独立游戏窗口；窗口关闭通过 `game:window` 事件同步状态。再次点「开始游戏」会重新加载 `/play/:id`。删除当前条目时也会先 `closeGameWindows(id)` 再删文件；`library:windows` 返回仍在运行的窗口 id，用于启动/刷新后恢复按钮状态。

### 6.5 网页浏览流程

1. 主界面点「网页浏览」→ `browser:open` → 创建 1280×860 的浏览器窗口，加载 `/browser`。
2. `/browser` 里是一个 `<webview id="view">`，地址栏、前进/后退/刷新、「解析此页」。
3. `did-attach-webview` 拿到 guest 后：
   - 先 `loadURL('about:blank')`，等 120 ms，再 `guest.debugger.attach('1.3')`（刚创建就 attach 会把网络服务带崩）；
   - `Page.enable` → `Page.addScriptToEvaluateOnNewDocument({ source: injection, runImmediately: true })`；
   - 后续每次导航都在 document start 执行注入。
4. 注入内容（`buildBrowserInjection`）：
   - 跳过 `localhost`/`127.0.0.1`；
   - 把 4399 的 `http://` 资源重写为 `https://`；把 `cdn.comment.4399pk.com/control/ctrl_mo_v5.swf` 改到本地 `/vendor/4399/ctrl_mo_v5.swf`；
   - 设置 `window.RufflePlayer.config`（`publicPath` 本地、`autoplay:on`、`allowNetworking:all`、`allowScriptAccess:true`、`upgradeToHttps:false`、`openUrlMode:deny`、`polyfills:true`）；
   - 4399 页面上让 `getElementById('testplayer1'/'testplayer')` 返回带 `checkflash()` 的占位对象；
   - 隐藏 `Anti_open` / `Anti_mask` / `Anti_dialog`，用 MutationObserver 持续处理；
   - 把 `vendor/ruffle/ruffle.js` 全文拼进注入脚本，让 Ruffle 接管页面里的 `embed/object`；
   - 仅对 `/flash/<数字>[_数字].htm` 启动 `reveal4399()`：每 250 ms 检查是否出现 `ruffle-embed/ruffle-player`，出现后隐藏 `#addiv`、`#loadingdiv`，`#pusher` 高度归零，显示 `#swfdiv`；持续 30 秒（120 次）。
5. `window.open` 一律 deny，改为当前 webview 导航（`setImmediate` 延后一帧，避免宿主窗口崩溃），地址栏同步，仍可“解析此页”。
6. 安全边界：guest `contextIsolation:true`、`nodeIntegration:false`、`sandbox:true`；注入只作用于 `http(s)` 且非本机地址。
7. 网页内只运行页面 SWF，不抽取内嵌游戏；205551 这类壳游戏在网页里会停在游戏自身加载页，需要解析入库后由播放器抽取。

### 6.6 网络层与本地服务

- 默认 session 把 **HTTP** 请求代理到本地服务：`proxyRules: 'http=127.0.0.1:<port>'`；HTTPS 不走本地代理。
- `onBeforeRequest`：
  - `cdn.comment.4399pk.com/control/ctrl_mo_v5.swf` → 本地 `/vendor/4399/ctrl_mo_v5.swf`；
  - 广告/统计域名 → `cancel: true`（`PRELOADER_ALLOW` 例外，见 `blocklist.js`）。
- `onBeforeSendHeaders`：播放器/浏览器 guest 的外链请求补当前游戏的 `Referer` 和 Cookie（优先从默认 session 的 Cookie 读，回退 `item.cookie`）。
- `onHeadersReceived`：仅播放器/浏览器 guest 的非本地请求补 CORS（`Access-Control-Allow-Origin: *` 等），因为 Ruffle 用 fetch 拉跨域素材。
- 本地服务绑定 `127.0.0.1`，但对外 origin 用 `http://localhost:<port>`：
  - 4399 壳用 `location.hostname` 判断是否 4399 域，只有 `localhost` 会跳过 `start_remote()`；`127.0.0.1` 会尝试连远程服务。
- 鉴权：启动 URL `/?t=<token>` 种 `ap_session=<token>; HttpOnly; SameSite=Strict; Path=/`；除 `/vendor/ruffle/*`、`/vendor/4399/*` 外都要求该 Cookie。
- CSP：`script-src 'self' 'unsafe-eval' 'wasm-unsafe-eval' blob:`；`/play` 额外加 nonce；允许 WASM / eval 是 Ruffle 与 4399 壳的硬需求。
- `/m/:id/:b64/:path`：把 base64url 编码的原始目录拼回目标 URL，带当前游戏 Referer/Cookie 去取；缓存键是 URL 的 SHA-1，写 `cache/<sha1>` + `.meta.json`；命中加 `X-Ap-Cache: HIT`；`AP_OFFLINE=1` 时未缓存直接 504。
- `/file/:id/...`：只读条目目录，防目录穿越；主 SWF 请求优先返回 `play.swf`。
- `/vendor/*`：免鉴权 + CORS，供网页 guest 跨域拉 Ruffle 与 4399 控制器。

## 7. 4399 / 7k7k 解析与 205551 加壳

### 7.1 为什么不只是“抓一个 SWF”

- 4399 页面可能把 SWF 地址放在 `_strGamePath`、`_winPath`、`_htmlPath` 等变量里，也可能只用 `embed/object` 或运行时才请求。
- 页面上常有 3 KB 的 `cell.swf` 广告占位；必须过滤。
- 部分游戏声明的地址实际是 HTML 包装页，真正的 SWF 以相对路径嵌在 HTML 里；需要跟进去。
- 页面可能夹带对方站点的广告 SWF；用站点归属打分压低。
- 部分游戏外壳会把真实游戏以 `DefineBinaryData` 内嵌，并检测“是否被 Loader 载入”。

### 7.2 40779（普通包装页）

- 页面声明的是 HTML 包装页，里面再引用真正的 SWF。
- Inspector 检测到 HTML 后提取 `.swf` 引用，用包装页 URL 作 Referer 重新下载，候选 `via=wrapper` 优先级 4。
- 实测：候选 1 个，`main.swf` 3,474,287 B，进入「3D极速飙车」标题页。

### 7.3 205551（三层拦截）

这是本项目最关键的兼容性修复，详细逆向见 `docs/FlashGamer-实现复现.md` §4.3.2。三层依次是：

1. **播放器参数校验**：
   - 壳读取 `loaderInfo.parameters`（flashvars），要求 `allowScriptAccess=always`、`allowNetworking=all`、`allowFullScreen=true`；
   - 壳还会通过 ExternalInterface 找到播放器元素，按 `nodeName` 区分 OBJECT/EMBED，读 `allowScriptAccess`/`allowNetworking` 与参数表比对；不匹配就 `dispose()` 并用字符串 `setTimeout` 执行 `cloneNode()+replaceChild` 重新挂载；
   - 修复：`buildBoot` 的 `parameters` 合并 `DEFAULT_FLASHVARS`；`player.html` 把 `<ruffle-player>` 伪装成 `EMBED` 并设置属性；拦截含 `fl_obj`/`cloneNode` 的字符串 `setTimeout`；
   - 本地页面必须用 `localhost`（不是 `127.0.0.1`）；
   - 4399 控制器 SWF 与版本 XML 通过 `PRELOADER_ALLOW` 放行，`ctrl_mo_v5.swf` 重定向到本地副本。
2. **反加壳检测**：
   - 内层游戏检查 `loaderInfo.loader != null` 且当前页面不在 4399 域名白名单，命中就弹「不允许加壳运行 / No running in a loader.」并中止；
   - 改参数绕不过去，必须改变“谁在顶层播放”。
3. **抽出内嵌 SWF 顶播**：
   - 外层壳用 tag 87（`DefineBinaryData`）内嵌真实游戏；
   - `swf-embed.js` 解压 FWS/CWS，遍历标签，取 ≥1 MiB 且以 FWS/CWS/ZWS 开头、声明长度合理的最大的内嵌段；
   - 只有带 `No running in a loader` 标记的壳才抽取，避免误伤普通 SWF；
   - 抽取结果写 `items/<id>/play.swf`，播放时作为顶层影片；`loaderInfo.loader` 为 null，反加壳检查通过；
   - 抽取幂等：`play.swf` 已存在且 >1 MiB 就复用。

实测：205551 外层 `main.swf` 69,072,554 B；内层 `play.swf` 69,431,196 B；800×600、30 fps；进入选人界面。40779 与已抽取内层再跑抽取器都返回 null，不会误伤。

### 7.4 7k7k

解析路径与 4399 共用 Inspector，但 7k7k 的播放器壳没有做专门适配；本机只验证过页面解析，没有逐游戏验证。遇到 7k7k 问题，先判断是解析还是播放兼容性，不要假设与 4399 完全一致。

### 8.2 检查与选择

- `check()` 用 `Promise.all` 并发拉取，每个 URL 加 `?t=<时间戳>`、`cache: no-store`、12 s 超时、256 KB 上限。
- 每份清单独立校验：版本格式、至少一个合法 asset、URL 必须是 HTTPS（开发允许 `127.0.0.1`/`localhost` 的 HTTP）、SHA-256 64 位十六进制、size > 0。
- 取所有成功源中的**最高版本**；同版本的所有可用源组成 `candidates`，下载时按源顺序回退。
- 版本比较支持 `x.y.z` 与 `-prerelease` 后缀；同号正式版大于预发布版。

### 8.3 下载与安装

- 下载在独立 session `flash-gamer-updater` 中进行，不挂本地代理、不注请求头，跟随系统代理；这样不会把更新请求送进本地 4399 代理。
- `Readable.fromWeb(res.body)` 流式写 `.part`，边写边算 SHA-256，进度通过 `update:progress` 推给界面。
- 完成后校验 `size` 与 `sha256`，通过才 `rename` 成正式文件；失败自动尝试下一条候选。
- 超时 10 分钟；包体上限 400 MB；只接受 HTTPS（开发允许本地 HTTP）。
- `update:install` 用 `shell.openPath` 打开 NSIS 安装程序，1.2 秒后退出主程序；不静默执行、不自动重启。
- 更新只替换程序文件；游戏库在用户数据目录，不受影响。

### 8.4 界面

- 主界面左下角「检查更新」按钮。
- `#updateModal`：版本号、发布日期、大小、更新说明、进度条、状态、稍后 / 下载并安装。
- 启动 6 秒后自动静默检查；有更新才弹窗；`AP_UPDATE_DISABLE=1` 关闭，`AP_SMOKE` 设置时也不自动检查。

### 9.2 安装程序

```bash
npx electron-builder --win nsis --x64 \
  --config.directories.output=release/build-0.3.3-dir \
  --config.electronDist=release/electron-dist-45.1.0
```

产物先落在 `release/build-0.3.3-dir/FlashGamer-0.3.3-setup.exe`，发布时需要复制到 `release/FlashGamer-0.3.3-setup.exe`（`release/` 根目录才是发布位置）。不要直接把 `--config.directories.output` 指到 `release` 根，避免覆盖历史同名文件。

为什么要 `--config.electronDist`：这台机器上 Qoder 的索引进程会打开工作区里的 `.asar` 文件；electron-builder 把 `win-unpacked.tmp` 改名为 `win-unpacked` 时，`default_app.asar` 被占用会报 `EPERM/EBUSY`。用已解压的 Electron 目录可以绕过“解压后改名”这一步。用 Sysinternals Handle 定位到的占用者是 `Qoder.exe`，不是程序自身的问题。

若没有现成的 `electron-dist-45.1.0`，可以先解压 Electron 到独立目录，或关闭占用后重试；不要删除 `release/` 里的历史目录。

`build/installer.nsh` 在安装目录写入 `installed.marker`；程序据此把数据放到 `%APPDATA%\Flash Gamer\FlashGamerData`，而不是安装目录。

### 9.3 免安装 zip

正式 zip 的顶层必须是 `FlashGamer-0.3.3/`，不能多一层 `.tmp-pack-033/`。

```bash
mkdir -p .tmp-pack-033/FlashGamer-0.3.3
cp -r release/build-0.3.3-dir/win-unpacked/. .tmp-pack-033/FlashGamer-0.3.3/
rm -f .tmp-pack-033/FlashGamer-0.3.3/resources/default_app.asar
(cd .tmp-pack-033 && ../node_modules/electron-winstaller/vendor/7z.exe a -tzip -mx=5 \
  ../release/FlashGamer-0.3.3-portable.zip FlashGamer-0.3.3)
```

验证（回到项目根，或用绝对路径）：

```bash
7za t release/FlashGamer-0.3.3-portable.zip
# 或使用 electron-winstaller 自带的 7z：
./node_modules/electron-winstaller/vendor/7z.exe t release/FlashGamer-0.3.3-portable.zip
```

第一次直接在项目根执行 `7z a ... .tmp-pack/FlashGamer-0.3.2` 会压出 `.tmp-pack/FlashGamer-0.3.2/` 多一级目录；v0.3.2 发布前已重打并替换资产。v0.3.3 改用 `.tmp-pack-033`，顶层正确。新版本不要再犯。

清理 `.tmp-pack-033` 时可能遇到 `Device or resource busy`：Qoder 索引进程会打开里面的 `resources/app.asar`。不要为了删临时目录去结束 Qoder；留着即可。

### 9.6 发布新版本时的顺序

1. 改 `package.json` 和 `package-lock.json` 的版本号（两处必须一致）。
2. 更新 `README.md` 版本表、更新说明；更新 `site/index.html` 的版本徽章、下载文件名、SHA-256 区块，并同步 `site/dist/`。
3. 打包安装程序 → 把 setup 复制到 `release/` 根目录 → 组装 portable zip → 计算 SHA-256 与大小。
4. 更新 `site/updates/win-x64.json` 的 `version/publishedAt/notes/assets`（大小与哈希必须与文件一致）。
5. 提交并推送（先确认；不要 force push）。GitHub Pages 工作流只在 `site/**` 或 workflow 变化时触发。
6. **先创建并推送 tag**：`git tag vX.Y.Z <commit> && git push origin vX.Y.Z`。没有远端 tag 就直接创建 Release，GitHub 会返回 422 `tag_name is not a valid tag`。
7. 创建 GitHub Release 并上传 setup 与 portable zip；两个包都超过 100 MB，用 `uploads.github.com` 流式上传，API 返回的 `digest` 必须与本地 SHA-256 一致。**不要打印 token**。
8. Qoder Sites：用新的 `actionId` 调 `prepare_site`，复用原 `projectId`；成功后 `publish_site`，`get_publish_status` 确认 `published:true`。
9. 验证三个清单 URL、GitHub Release 资产、官网下载链接、安装/免安装包；安装版回归一次停止运行与重新开始。

## 11. 测试与自动化验收

### 11.1 环境变量总表

所有变量都在 `src/main.js` / 子模块中读取。smoke 产物默认写到 `AP_DATA_DIR`（或 `data/`），不是 `docs/`；需要入库的截图要手动复制。

| 变量 | 作用 |
| --- | --- |
| `AP_DATA_DIR` | 指定临时数据目录，避免污染真实游戏库 |
| `AP_SMOKE` | `full`：解析 URL → 入库 → 播放；`replay`：回放已入库条目；其他真值可配合 browser/update 子测试 |
| `AP_SMOKE_URL` | `full` 模式的游戏页 URL |
| `AP_SMOKE_ITEM` | `replay` 模式的条目 id |
| `AP_SMOKE_WAIT` | 播放等待毫秒数，默认 7000；69 MB 游戏建议 45000 |

### 11.2 运行 smoke 的注意点

- 先 `unset ELECTRON_RUN_AS_NODE NODE_OPTIONS`，否则 Electron 可能按 Node 模式启动。
- 安装版可能正在运行并占用单实例锁；用 `--user-data-dir` 指定独立目录，并用 `AP_DATA_DIR` 指定独立数据目录。
- 无桌面会话时 `capturePage()` 可能返回 `UnknownVizError` 或旧帧；`AP_SMOKE_OFFSCREEN=1` 是可靠方式。
- smoke 会改写 `AP_DATA_DIR` 下的 `library.json`、截图和 `smoke.json`；不要指向用户真实数据。
- 69 MB 的 205551 首次抽取 `play.swf` 需要时间；replay 用 45 s 等待更稳。
- 4399 的“开始游戏”有时是空锚点或弹窗；网页 Flash smoke 可能需要坐标点击或 CDP 点击，坐标会随页面布局变化。

### 13.3 功能限制（继承自实现文档）

1. **加壳变体**：只处理“外层用 `DefineBinaryData` 内嵌单个完整游戏、带 `No running in a loader` 标记”的壳；多段内嵌、加密内嵌、自行解密后 `Loader` 载入的变体会返回 null，表现停在加载页。
2. **CJK 设备字体**：205551 的 UPDATE 等弹窗使用宋体/微软雅黑/黑体设备字体，Ruffle Web 端没有映射，部分文字显示缺字或方块，不影响进入游戏。
3. **AS3 兼容性**：Ruffle 对复杂 AS3/Flex 覆盖有限，部分游戏能加载但交互异常。
4. **登录态范围**：Cookie 注入解决“游戏请求带登录 Cookie”，但有些 4399 接口还要求页面 JS 桥（`4399api_*` 回调）；本机监听 30 秒未发现壳发起 JS 调用，故未实现桥接。
5. **HTTPS 证书**：`onHeadersReceived` 只为播放器/浏览器 guest 补 CORS，不忽略证书错误；老站点自签证书会直接失败。
6. **广告拦截误伤**：域名级黑名单可能误伤同域必要接口；遇到加载卡住先用正常网络复测，并把必要路径加入 `PRELOADER_ALLOW`。
7. **7k7k**：解析路径与 4399 共用，播放器壳未专门适配；仅验证页面解析，未逐游戏验证。
8. **网页内不抽取内嵌游戏**：205551 这类壳游戏在网页里会停在游戏自身加载页；要解析入库后由播放器抽取 `play.swf`。
9. **本机网络**：直连 Qoder/GitHub 可能 TLS reset / DNS 失败；用系统代理 `127.0.0.1:7890`。更新器使用独立 session 跟随系统代理。
10. **无代码签名**：SmartScreen 可能提示“未知发布者”；官网提供 SHA-256。
11. **单实例锁 + 安装版运行**：会阻止开发实例启动；不要杀用户进程，用独立 `--user-data-dir`。
12. **端口不固定**：43199 被占用时自动 +1；不要写死端口，读 `config.json` 或日志。
13. **`capturePage()` 在无桌面会话不可靠**：用 `AP_SMOKE_OFFSCREEN=1`。
14. **4399 页面结构变化**：解析与遮挡层逻辑依赖页面变量/DOM；页面改版后可能需要更新 Inspector 或注入规则。

## 16. 术语

| 术语 | 含义 |
| --- | --- |
| SWF | Flash 影片文件；签名 `FWS`（未压缩）、`CWS`（zlib 压缩）、`ZWS`（LZMA 压缩）。 |
| Ruffle | Rust 编写的 Flash 模拟器，编译为 WASM，在浏览器/Electron 中运行 SWF。 |
| Inspector | 本项目隐藏窗口解析器，负责加载页面、抓包、提取候选。 |
| 包装页 | 声明为 SWF 实际返回 HTML 的地址；真正 SWF 在 HTML 里。 |
| `DefineBinaryData` | SWF tag 87，可把任意二进制（这里是一整个 SWF）嵌在影片里。 |
| 反加壳 | 内层游戏检测 `loaderInfo.loader != null` 且不在 4399 域，命中就拒绝运行。 |
| `play.swf` | 从加壳外层抽出的内层游戏；存在时优先于 `main.swf` 播放。 |
| `ap_session` | 本地服务的鉴权 Cookie，防止其他本机网页直接访问播放器/库接口。 |
| NSIS | Windows 安装程序生成器；本项目用 electron-builder 的 nsis target。 |
| `installed.marker` | 安装目录里的标记文件；程序据此把数据放到 `%APPDATA%`。 |
| smoke | 主进程内置的自动化验收模式，用 `AP_SMOKE*` 环境变量驱动。 |
